# 酷狗 .kgg 转换工具

把酷狗音乐下载的 `.kgg` 加密音频解密成**可正常播放的音频**，并（可选）转成 MP3。

零第三方依赖，只用 Node.js 内置模块 + 你本机已装的 ffmpeg。

---

## 一、重要前提（先看这个，能省很多时间）

`.kgg` 的密钥**不在文件里**，而在本机酷狗客户端的密钥库 `KGMusicV3.db` 中。因此：

1. **必须在下载这首歌的同一台设备、同一账号上解密。** 换台机器就算把 `.kgg` 拷过去也解不开。
2. **这首歌必须在酷狗里至少完整播放过一次。** 密钥是播放后才写入密钥库的。
3. 密钥库的位置：`%APPDATA%\KuGou8\KGMusicV3.db`（工具会自动找，也支持手动指定）。

如果这两条不满足，工具会明确告诉你"密钥库里没有这条 keyId"，而不是给你一个坏文件。

---

## 二、怎么用

### 方式 1：双击（最省事）

把 `.kgg` 放到项目根目录或 `input\` 下，然后双击：

| 文件 | 作用 |
|---|---|
| `bin\convert.cmd` | 解密 + 转 MP3，产物进 `output\` |
| `bin\probe.cmd` | 只"体检"：打印头部信息和密钥命中情况，**不写任何文件** |
| `bin\ui.cmd` | 打开本地网页界面（自动开浏览器） |

### 方式 2：命令行

```bat
node src\cli.js                             :: 转换项目目录 + input\ 下所有 .kgg
node src\cli.js "D:\某处\歌曲.kgg"           :: 指定文件
node src\cli.js --probe                     :: 只体检
node src\cli.js --no-mp3                    :: 只解密出原始音频，不转 MP3
node src\cli.js --bitrate 256k              :: 换 MP3 码率（默认 320k）
node src\cli.js --force                     :: 覆盖已存在的产物
node src\cli.js --deep-check                :: 转码后再整片解码校验（更慢更保险）
node src\cli.js --db "D:\...\KGMusicV3.db"  :: 手动指定密钥库
node src\cli.js --key mykey.txt             :: 改用密钥文件（每行 keyId$EnKey）
```

退出码：`0` 全部成功，`1` 有失败项，`2` 致命错误（比如找不到密钥库）。

### 方式 3：网页界面

双击 `bin\ui.cmd`，浏览器会打开 `http://127.0.0.1:8787`。可以勾选文件、看进度条、看每个任务的校验结果。

界面里"选择文件…"调用的是 **Windows 原生文件选择框**，所以能直接挑任意目录里的 `.kgg`（挑中的文件会被临时授权，其它路径一律拒绝）。

#### 输入 / 输出目录

界面上方会同时显示**当前目录**和它是不是**默认目录**：

| | 默认值 | 说明 |
|---|---|---|
| 输入目录 | `<项目>\input` | `.kgg` 从哪里找。可以改成酷狗的真实下载目录，例如 `D:\KuGou\KugouMusic` |
| 输出目录 | `<项目>\output` | 产物存到哪里 |

这些值存在设置文件 `config\settings.ini` 里，界面上的按钮和直接编辑文件是**等价**的（详见下一节）。

点"修改…"后会展开一个**内联输入框**，两种方式随你选：

1. **直接粘贴路径**（推荐）—— 从资源管理器复制地址栏粘进去，回车即可，不用一层层点。
2. **点"浏览…"** 用 Windows 原生目录选择框挑。这里用的是**新版对话框**（`IFileOpenDialog` + `FOS_PICKFOLDERS`），
   顶部有地址栏/面包屑，也能直接粘贴路径跳转；旧版的 `FolderBrowserDialog` 只有一棵树，所以没有采用。

其它行为：

- **取消是静默的**：不管是点"取消"按钮、按 Esc、还是关掉系统选择框，都只是收起编辑框，**不会弹任何提示**。
- 目录不存在时，会问一句"是否创建"，确认后才创建 —— 而且只会创建**最后一级**（父目录必须已存在），
  避免手滑粘贴出一整条目录树。输出目录还会检查是否可写。
- 路径两边带引号也能识别（从某些地方复制过来常常带引号）。
- 这只影响网页界面；命令行始终用项目内的 `input\` 与 `output\`。

#### 设置文件 `config\settings.ini`

界面上方还会显示这个文件的路径，并有两个按钮：**打开配置文件**（在资源管理器里定位到它，可直接用记事本改）
和 **重新读取配置**（手改完之后点一下；其实刷新页面也会自动重新读）。

```ini
# 留空 = 使用程序内置的默认路径
inputDir=
outputDir=

# 改成你自己的路径就像这样（不需要转义、不需要加引号）：
# inputDir=D:\KuGou\KugouMusic
# outputDir=E:\Music\converted
```

**为什么用 ini 而不是 JSON？** 因为 Windows 路径全是反斜杠，而 JSON 里反斜杠是转义字符：

| 你写的 | JSON 的结果 | ini 的结果 |
|---|---|---|
| `D:\KuGou` | **解析直接失败**（`\K` 不是合法转义） | `D:\KuGou` |
| `D:\\KuGou` | `D:\KuGou`（正确，但"两个才等于一个"容易记反） | `D:\KuGou` |
| `D:\\\\KuGou` | `D:\\KuGou` —— **静默变成错路径，还不报错** | `D:\\KuGou` 归一化后仍是 `D:\KuGou` |

ini 所见即所得，还能写 `#` 注释。代价是自己解析（约 40 行），对零依赖项目划算。

**整个项目文件夹可以随便搬家**，配置不会失效：

- **留空就是默认**——默认路径是运行时按项目位置算出来的，搬到哪都跟着走；
- 也可以写**相对路径**（`input`、`output`、`..\素材\kgg`），相对的是**项目目录**，同样跟着项目走；
- 界面上改目录时，**如果选的是项目内的目录，会自动存成相对路径**（选到默认目录则存成空）；
- 只有写到**项目外面**的绝对路径（例如 `D:\KuGou\KugouMusic`）才依赖盘符位置。

界面上会把"你写的是相对路径，解析成了哪个绝对路径"明确提示出来。

**路径写法很宽松**，下面这些都会归一化成同一个路径：

```ini
inputDir=D:\KuGou\KugouMusic       # 单反斜杠
inputDir=D:/KuGou/KugouMusic       # 正斜杠
inputDir=D:\\KuGou\\KugouMusic     # 双反斜杠
inputDir=D://KuGou//KugouMusic     # 双正斜杠
inputDir="D:\KuGou\KugouMusic"     # 带引号（资源管理器复制路径常见）
inputDir=%USERPROFILE%\Music\kgg   # 环境变量会展开
inputDir=input                     # 相对项目目录
inputDir=..\素材\kgg                # 相对项目目录，可以往上走
```

归一化过、展开过、按相对路径解析过，界面都会**提示出来**（"你写的是 X，程序理解为 Y"）。

**写错了不会被静默忽略**，界面会带行号报出来：

- 不是 `键=值` 的行
- 未知的设置项（并列出可用的键）
- 同一个键写了两遍
- 目录不存在 / 不是目录 / 没有写权限（同时显示"你写的"和"程序理解的"）

**文件可以放心删**：下次启动会自动重新生成一份（带注释和示例，值留空）；运行期间删掉的话，
会自动回退到内置默认路径并提示你，点"打开配置文件"也会顺手重建。总之
**"值留空"、"键不写"、"文件被删" 三种情况行为完全一致**：都用内置默认路径。

> 从旧版本升级的话，原来的 `.ui-config.json` 会在首次启动时自动迁移到这个文件并删除。

#### 已转换标记

文件列表里的每一首歌都会带一个状态标记，并且**新文件排在最前面**：

| 标记 | 含义 |
|---|---|
| `新文件` | 输出目录里还没有它的产物 |
| `部分转换` | 只有一半（例如解出了 `.ogg` 但还没有 `.mp3`），转换时会补齐 |
| `已转换` | 该有的都有了（同时显示"已有 .ogg + .mp3"） |

配套两个动作：

- **"只选未完成的"** 按钮：一键勾选所有非"已转换"的文件 —— 也就是优先转新歌。
- **"覆盖已转换的"** 复选框：不勾时，你即使勾了已转换的文件，它也会被**跳过**（并告诉你跳过了哪些）；
  勾上才会重新转换并覆盖产物。这样不会手滑把已经转好的东西白跑一遍。

转换结束后列表会自动刷新，标记立刻跟着更新。

#### 密钥库自动刷新

界面是常驻进程，如果在它运行期间你又去酷狗下载了新歌，直接点"开始转换"就行 ——
缓冲区里查不到这首歌的密钥时，工具会先比对密钥库指纹（大小 + mtime），发现库被更新过就自动重新解密再查一次；
没更新就直接返回，不做无谓的 38MB 解密。界面顶部会显示内存里这份密钥库的加载时间，也可以点"重新加载密钥库"手动触发。

> **端口被占用时**（多半是上一个界面窗口没关），启动会明确提示并顺延到下一个端口。
> 这时请关掉旧窗口再重新双击 `bin\ui.cmd`，否则你会对着跑旧代码的旧界面，误以为改动没生效。

## 三、产物说明

`output\` 目录下：

| 文件 | 说明 |
|---|---|
| `<歌名>.ogg` / `.flac` / `.mp3` | **解密出的原始音频**，这是唯一的原件 |
| `<歌名>.mp3` | 转码后的 MP3（320k CBR，带 ID3 标签） |

关于源格式要有个心理准备：**酷狗标的"320"是质量标签，不代表一定是 MP3**。本目录里那首歌实测是 **Ogg Vorbis**（平均 253 kbps）。Vorbis 本身就是有损格式，所以：

- 如果源是 FLAC/WAV（无损），转 MP3 是"无损 → 有损"，原始文件保留下来很有价值；
- 如果源是 Ogg Vorbis（有损），转 MP3 属于**二次有损**，无法避免。建议保留 `.ogg` 作为底本，MP3 只用于兼容播放。

## 四、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `密钥库里没有这首歌的密钥` | 没播放过，或不是本机/本账号下载 | 用酷狗完整播放一次；确认文件来源 |
| 新下载的歌在网页界面里报"没有密钥" | 界面加载密钥库在前、下载在后 | 已自动处理：转换时会检测密钥库变化并重新加载。若仍失败，点"重新加载密钥库" |
| 界面打开的地址不是 8787 | 上一个界面窗口没关，端口被占 | 关掉旧窗口再重新双击 `bin\ui.cmd` |
| `找不到酷狗密钥库 KGMusicV3.db` | 没装酷狗，或装在非常规位置 | 用 `--db <路径>` 指定 |
| `密钥库第 1 页完整性校验失败` | 酷狗更换了密钥库格式 | 见 `docs/format-notes.md`，需要更新主密钥 |
| `不支持的 .kgg 加密版本 3` | 是旧版加密文件 | 本工具只实现了版本 5 |
| `解密结果自检未通过` | 密钥或数据不对 | 产物已被自动删除，请先跑 `bin\probe.cmd` 看命中情况 |
| `找不到可用的 ffmpeg` | 没装或不在 PATH | 装 ffmpeg，或用 `FFMPEG_PATH` 环境变量指定 |
| 转码很慢 | 320k MP3 编码本来就慢 | 4 分钟的歌约 20~40 秒属正常 |

回归测试：`npm test` 会跑三个脚本 ——

- `tests\config-ini.test.js`：设置文件的解析与路径容错（单/双/正反斜杠、引号、BOM、环境变量、写错的行）
- `tests\outputs-status.test.js`：产物状态判定（已转换 / 部分转换 / 新文件）的边界情况
- `tests\key-store-reload.test.js`：常驻界面能否识别启动之后才下载的新歌密钥

## 五、目录结构

```
KugoToMP3\
├─ src\
│  ├─ cli.js                    命令行入口
│  ├─ kugou\                    酷狗专有格式这一层
│  │  ├─ locate.js              定位密钥库
│  │  ├─ db-cipher.js           解密密钥库（分页 AES-128-CBC）
│  │  ├─ keymap.js              keyId → EnKey 映射（可自动刷新）
│  │  ├─ header.js              解析 .kgg 头部
│  │  ├─ ekey.js                解包 EnKey（Tencent-TEA）
│  │  ├─ qmc2.js                音频流解密（QMC2）
│  │  └─ audio-decrypt.js       核心流程（流式 + 自检）
│  ├─ audio\
│  │  ├─ sniff.js               明文格式嗅探
│  │  ├─ verify.js              产物结构校验
│  │  └─ transcode.js           ffmpeg 转 MP3
│  └─ web\                      本地网页界面
│     ├─ server.js              HTTP 服务与接口
│     ├─ tasks.js               任务队列
│     ├─ outputs.js             产物状态判定（已转换标记）
│     ├─ config.js              输入/输出目录配置的读写
│     ├─ pick-dialog.ps1        原生文件/目录选择框（新版文件夹对话框）
│     └─ public\                页面（原生 JS，无框架）
├─ bin\                         双击即可运行的 .cmd
├─ tests\                       回归测试
├─ config\
│  └─ settings.ini              输入/输出目录设置（自动生成，可直接编辑）
├─ input\                       默认输入目录
├─ output\                      默认输出目录
└─ docs\format-notes.md         格式细节与算法出处
```

> ⚠️ **维护提示：`bin\*.cmd` 里只能写纯 ASCII。**
> `cmd.exe` 是按系统 OEM 代码页（中文 Windows 是 GBK/936）解析批处理文件的。
> 如果把这些文件存成 UTF-8 并写入中文，中文会被解码成乱码，而乱码字节会破坏语句结构，
> 结果是脚本从第一行就报错、双击时窗口一闪而过。所以：批处理只放控制流和英文提示，
> **所有中文输出都交给 Node 打印**（批处理里先 `chcp 65001 >nul` 把控制台切成 UTF-8）。
>
> 同理，`src\web\pick-dialog.ps1` 也是 **ASCII-only**：Windows PowerShell 5.1 在没有 BOM 时
> 按 ANSI 读取 `.ps1`，写中文一样会被弄乱。对话框标题/过滤器用英文，中文界面文字都在网页里。

## 六、隐私与安全

- **解密的明文密钥库只在系统临时目录落地，用完立即删除。** 它包含你全部的下载记录和 EnKey，工具不会把它写进项目目录。
- 即使进程被**强行结束**（任务管理器结束进程等，JS 来不及清理），下次运行时也会自动把这类孤儿文件删掉：
  启动时扫一遍临时目录，太新的先放过（可能是别的进程刚开始解密、还没打开），其余的**直接尝试删除** ——
  Windows 上正被打开的文件会拒绝删除，所以删成功就是垃圾、删失败说明还有活进程在用（保留）。
  不用"文件名里的进程号是否还活着"来判断：那是猜，进程号会被系统复用，孤儿就永远清不掉了。
- 网页界面**只监听 `127.0.0.1`**，局域网和外网都访问不到；并校验 Host 头以防 DNS rebinding。
- 服务端只接受**当前输入/输出目录、项目目录内的路径**，外加你通过原生对话框亲手选中的文件，不做任意路径读取。
  你把输入/输出目录改成别处（例如 `D:\KuGou\KugouMusic`）时，读写范围就只扩大了这两个目录，不会变成"任意路径都能读写"。
- 目录配置存在 `config\settings.ini`（`config\.gitignore` 已屏蔽），里面是本机绝对路径，不参与版本管理；
  密钥材料（`*.db`、`*.key`）同样不会入库。

## 七、依赖与出处

- **运行时**：Node.js ≥ 22.5（用到内置 `node:sqlite`）；MP3 转码需要 `ffmpeg`（含 `ffprobe`）。
- **npm 依赖**：无。`npm install` 不需要跑。
- **算法出处**：`.kgg`（KGG v5）的解密规格来自公开实现 ——
  [unlock-music 的 kgg-dec](https://git.unlock-music.dev/um/kgg-dec) 与
  [OpenConverter](https://github.com/nowa277/OpenConverter)（Apache-2.0）。
  本项目的代码是据公开规格独立实现，常量与规格保持一致。细节见 `docs/format-notes.md`。
